# GOINO/CONDY console increment

The `p6066` machine now runs original CAROM from reset through CPU and
memory checks and memory enumeration, then selects floppy controller E0.
With that controller removed (`-bus:floppy ""`), CAROM emits timeout lamp word
`8084` and loops at `80B6`. This is firmware behavior, not an emulator
unsupported-instruction stop. With FLODI installed, the first-read test retains
the startup lamp word FFFF. See [FLODI results](flodi-evidence.md).

## Implemented path

* PUCE ESE (`B1x4`) reads the selection byte through the normal memory system.
  Short selectors 12–15 use A only; odd/even byte addressing is preserved.
* PUCE DAE (`FCx0`) emits L(x) through an external-data callback carrying the
  current CPU level. These are transaction callbacks, not a finished bus.
* A separate `p6066_goino_device` owns the initial GOINO/CONDY console state.
  Selection name zero enables the direct level-4 path. Selection does not
  also act as a data strobe. Nonzero selection deselects this board.
* Output `40xx` clocks ECD0 into the CONDY 16-bit serial lamp register. The
  functional panel publishes the resulting word at each 16-strobe boundary.
  Other bits in the low byte do not affect the lamp data. CAROM issues 256
  transfers of `40FF`, leaving every lamp-register bit set.
* Output `20xx` feeds the display buffer. Each update consists of two
  preparation bytes and 222 visible columns, with seven dots per column.
  A new transfer suppresses rendering until all 224 bytes have arrived.
  Bit 7 controls a functional 4Hz column blink. The panel renders dots directly,
  with no font or text generated by the driver.
* Unsupported CPU words hold execution after reporting their address. The
  driver enables this development behavior so the UI remains inspectable;
  the CPU's default policy is still fatal. Reset resumes from CAROM. Editing
  PC through the debugger also releases the development stop.

## Functional UI

The embedded `p6066.lay` view includes the small display, console lamp labels,
four LED indicators, and a clickable **RESTART** control. F3 restarts the
machine; Tab opens MAME settings; Esc exits. The CPU STOPPED indicator is an
emulator diagnostic. The other lamp labels follow the console manual.

The seven console-labelled panels currently display lamp outputs. Their
physical button inputs, keyboard, interrupt requests and acknowledgements
are **not implemented**. RESTART is an emulator control, not a claim about a
physical P6066 button. LED indicators currently expose the raw register bits;
the LER1 driver circuit/blink and the cicalino monostable/audio remain to be
implemented. Calculator indication currently shows LAMX1; LAMX2 is preserved
in the register but its visual/color relationship remains to be resolved.

The display is blank on the current cold CAROM path because firmware has not
sent it a message before the floppy-controller timeout. The regression fixture separately exercises
its renderer with a synthetic PUCE program in RAM. Its diagonal pattern is
test data, not a recovered firmware screen.

## Evidence and limits

Primary source: Olivetti *GOINO e ASTAM e CONDY e ROMCA e TASTIERA — Descrizione
di Funzionamento*, STAC 670.30.1, in the parent project's
`reference/DocumentazioneP6060_P6066/Manuali STAC e di servizio/2L`.

| PDF pages | Evidence used |
|---|---|
| 8, 16 | Hardware name 00; direct level-4 selection; interruption masks selection |
| 9, figure 1.3 | `40xx` lamp strobe uses only ECD0; `20xx` display transfer |
| 14–15, 17–18 | 224 display transfers; 16 serial lamp transfers; ESE must not generate spurious commands |
| 51–52 | Two preparation bytes; buffer write/read transition; column blinking |
| 58–59, figures 16–18 | Console labels, 16-stage shift-register order and lamp/LED wiring |

CPU19 *Tabella Microistruzioni V2*, PDF pages 5–6, defines DAE and ESE.
The console manual calls its output transfers CAE, but the reference CAROM
uses DAE for lamp startup; GOINO's data strobe decode and ESE exclusion are
modelled at the transaction boundary. CAE and further command semantics have
not yet been implemented in the CPU.

Figure 18 gives the shift order used here (bit 0 receives the newest bit):
unused, TROM, unused, unused, LED3, LED2, LED1, LED0, LAMX1, LAMX2,
LAM5, LAM4, LAM3, LAM2, LAM1, LAM0.

The manual describes P6060 assemblies. Compatibility with the selected P6066
board revision still needs checking against the P6066 scans. The functional
model omits nanosecond strobes, counter power-on phase, lamp transitions while
shifting, display serial/multiplex timing and protection circuitry. Lamp
publication at complete words is a presentation approximation. Vertical dot
orientation and blink polarity remain provisional pending schematic checks.
The device uses deterministic reset values without claiming verified physical
reset behavior. Bus arbitration is implemented, but interrupt-owned GOINO selection remains absent;
the direct level-4 callback must not be treated as their implementation.
Save items cover partial transfers and outputs, but save/load integration has
not yet been tested. Sound is still flagged unemulated.

## Reproduce

Build using the command in [README.md](README.md). With the verified reference
image installed as `p6066/carom.bin` in a ROM directory:

```sh
./p6066 p6066 -rompath /path/to/roms -window -resolution 1100x520 -skip_gameinfo
```

ROM-free tests and CPU regression:

```sh
python3 scripts/puce/test_console.py
python3 scripts/puce/test_disassembler.py
python3 scripts/puce/test_cpu.py
python3 scripts/puce/test_word_memory.py
python3 scripts/puce/test_byte_memory.py
```

Full integration with the reference CAROM:

```sh
./p6066 p6066 -bus:floppy "" -rompath /path/to/roms -video none -sound none -nothrottle -skip_gameinfo -seconds_to_run 20 -autoboot_delay 7 -autoboot_script scripts/puce/test_console_mame.lua -snapview Console -snapname console-cold -snapshot_directory /path/to/results
```

The Lua test must print **three PASS lines**, with no Lua assertion errors:

1. Cold CAROM completes memory enumeration, selects E0, and reaches its
   timeout loop with lamp pattern 8084 and the expected bootstrap parameters.
2. Synthetic PUCE code verifies BMI byte lanes, selects from an odd memory
   byte, clocks lamp pattern A55A, and transmits 224 display bytes.
3. The panel restart resets CPU/console and repeats the entire cold path.

Snapshots `console-cold.png` and `console-fixture.png` capture the native MAME
layout. MAME can return zero even after a Lua assertion, so check the PASS
markers as well as the process exit status. No ROM bytes are in the scripts.

## Disk firmware entry checkpoint

With ME006 installed, original CAROM loads disk 121 and enters firmware at
word 1000, level 3. The saved functional panel has all lamps off at this
checkpoint; see `analysis/mame-p6066/bootstrap-validation/installed.png` in the
parent project. The earlier first-read checkpoint remains FFFF. No synthetic
lamp pattern is applied for either snapshot. [Bootstrap validation](me006-bootstrap.md)
describes the observer and the subsequent unsupported F400 console command.
