# PR 6610 thermal printer (functional rendering)

<!-- copyright-holders: Salvatore Paxia -->

The user requested a visible rendering of the printer output. The PR 6610 is
the P6066's integrated thermal dot-matrix printer; no PR 6610 board dump,
mechanical manual or service manual is available locally. This device is a
**functional rendering model built on the validated GOINO discard-output
handshake**, not a reconstruction of the ASTAM print engine or the DISL006
interface circuit.

Attach it at startup with `-bus:console:goino:options pr6610`. It replaces
the [discard-output printer](discard-printer.md) on the same connector, uses
the same command contract, and additionally renders the transferred columns
and feeds onto a paper roll.

The slot defaults to empty. `-bus:console:goino:options printer` selects the
older handshake-only card instead; these two values are alternatives, not
flags to combine. The console's PRINT ALL and NO PRINT buttons are separate
guest-visible inputs and still operate with either card. They do not select
the card or change the host rendering mode. Guest `CONFIGURE`/`OPTIONS`
printer choices stored on disk are likewise independent of the host slot
choice; attaching a card does not rewrite the guest's configuration.

The optional video board is another slot: add `-bus:video go011` alongside
`-bus:console:goino:options pr6610` to attach both. The default layout then
shows video, paper and console together, with individual views also available.
Without `pr6610`, the video-and-console layout is used; the handshake-only
`printer` card produces no paper image.
`-video none` is MAME's headless host video backend, not the GO011 slot
selection: omit it to see the combined layout on screen.

## Host view selector and paper feed

When both GO011 and PR 6610 are selected, the layout has clickable **VIDEO**,
**PRINTER** and **BOTH** buttons. They switch MAME's first display target
between the video-and-console, printer-and-console and combined
video/printer/console views without changing either device or the guest's
output routing. The lower console pane and selector remain visible with all
three buttons. The controls are above the console LCD, with the view selector
on the left and FEED on the right, at the same size as the console keys.
With only one output installed, the view selector is omitted
entirely. MAME's Video Options can still select its other views, including
the bare screen-only views.
The single-output artwork is half as wide as the combined artwork at the
same height. With the SDL3 backend, the P6066's host selector also resizes
the window to fit: 1278×704 content pixels for BOTH, 639×704 for VIDEO or
PRINTER, reduced uniformly if the monitor is smaller. A manually resized
window is not resized while dragging. Switching between VIDEO and PRINTER
keeps the exact window size, and clicking the current view does nothing.
Switching between either single-output view and BOTH adjusts the width
while retaining the current height and console size.

The **FEED** button appears in both PR 6610 layouts, including the
printer-only configuration, but not when the printer is absent or when the
handshake-only `printer` card is used. Each press advances the roll by one
1/6-inch text line (35 paper pixels); releasing the button does not advance it
again. It uses the normal continuous-feed and saved-page path, but does not
send a command to GOINO, transfer columns or modify printer handshake state.
These are emulator convenience controls, not documented P6066 panel buttons
or a model of the PR 6610's physical feed switch.

## Relationship to the discard-output printer

The GOINO connector stub (see [discard-printer.md](discard-printer.md)) models
the entire ESE-facing contract: command decode, request latches, arbitration,
level 2/3 ownership, status bits and the 6.3 ms pacing. That model was
validated with the GTL3.2 CATALOG regression. `p6066_pr6610_device` subclasses
the discard printer card and hooks two observables:

* **Column transfer.** Each column the stub discards is additionally rendered
  as one 7-dot matrix column at 1/70" pitch, then the carriage advances one
  pitch. The three leading blank columns of the ESE transfer cover the SLINN
  lead-in before the first printed column.
* **Feed.** Each feed event advances the paper by one UMO20 step (1/60").
  Half-pixel bookkeeping makes 10 steps the exact 1/6" interline and 6 the
  1/10" interline at 210 dpi.

Both observables are diffed from the stub's counters inside `tick()`, which
still calls `state.printer_tick()` first, so handshake timing is exactly the
validated discard-printer timing. At most one column or feed event is
generated per 6.3 ms tick by the request gating, so the diff never skips more
than one event.

## Rendering geometry

| Parameter | Value | Basis |
|---|---|---|
| Paper width | 210 mm (1736 px) | 210 mm roll at 210 dpi |
| Paper storage | 9" ring (1890 px), continuous feed | old rows retire to PNG pages without losing the live viewport |
| Live paper window | 1736×1271 pixels (about 6" high) | screen and exported paper use the same full-resolution bitmap |
| Horizontal resolution | 210 dpi | functional choice; column pitch 3 px = 1/70" |
| Vertical resolution | 210 dpi | functional choice; feed step 3.5 px = 1/60" |
| Column pitch | 3 px | the 1/70" matrix column pitch |
| Dot size | 2×2 px | visual approximation of a thermal dot |
| Left margin | 28 px | unverified; TBD |
| Head | 7 resistive elements | printed GOINO p.7, matrix column of 7 |

Rendered via the shared `bitmap_printer_device` with continuous feed. Its
configurable screen height remains 384 px for other printers. The PR 6610
uses a 1271 px live view and a 1890 px storage ring; printing stays 50 px
above the *bottom* of the live view while older lines move up through the
entire pane. The storage ring is larger than the view plus both 50 px feed
guards; retired rows are saved to PNG instead of silently overwritten.

## Layout and output finders

`p6066_printer.lay` combines the console group with the printer paper screen
(`bus:console:goino:options:pr6610:bitmap:screen`) in three views:
"Console and Printer", "Console", "Printer". The driver selects this layout
when the `pr6610` card is installed without GO011. With both cards installed,
`p6066_video_printer.lay` includes the GO011 framebuffer in the default
"Video, Printer and Console" view.
Both layouts display the full-resolution 1736×1271 paper source. It has
exactly the same aspect ratio (100×73.2143 layout units) as GO011's
560×410 framebuffer. The fixed 3×3 reduction and preview-only contrast
boost have been removed; MAME still scales the screen to the host pane.
The 384-row paper screen initially required a short 100×22.1198 viewport
to avoid vertically stretching the dots. That left the rest of the white
pane as inert background; the taller live window now makes it scrolling
paper instead; no static white filler remains behind it. Other bitmap printers
keep their 384-row default.

The card publishes live diagnostics through output finders:
`pr6610_columns` (rendered columns), `pr6610_feed_rows` (paper pixels fed),
`pr6610_head_x`, `pr6610_head_y`.

## Validation

The CATALOG regression (three CATALOG listings, then NEW / 10 DISP 12345 /
20 END / RUN twice, all through ordinary keyboard input) passes with the
card installed: 3,216 rendered columns and 300 feed events (1,050 fed rows)
exactly match the discard-printer counters, the carriage returns to the left
margin, and both BASIC runs display 12345 and return READY. Reproduction
notes and observer script are in the parent project at
`analysis/mame-p6066/pr6610/catalog-regression/`.

The rendered paper shows the three catalog listings with the observed
interline gaps; snapshot pixels are captured for offline checks.
With the taller window, a video-and-printer run of three CATALOG listings
retained ink from screen rows 346 through 1205; the newest row remained near
the bottom. A separate seven-listing run traversed the 1890-row ring:
9,100 columns and 2,205 feed rows yielded two saved paper PNGs containing
56 and 336 ink rows respectively (392 total, seven times 56).
In a simultaneous video-and-printer CATALOG run, the first two visible
printer ink bands were 70 paper pixels apart (20 GOINO feed steps at 3.5 px
each), while two neighboring GO011 bands were 20 video pixels apart. This
corresponds to two line advances on both outputs, not double-counted printer
feed; the two devices have different native pixel grids. The live layout
previously used the video pane's aspect for the much wider paper screen.

With GO011 and PR 6610 attached simultaneously, a compilation-disk CATALOG
exposed a renderer defect: feed could overlap transfer end, so the old
`!printer_running && !printer_feeding` condition left the carriage advancing
across multiple lines. A read-only 50-second observer measured 70 feed rows
with the head still at x=280, then 761 transferred columns with x saturated at
1735 (the right paper edge). The renderer now returns whenever the transfer
ends, even during feed. The independent render test covers a feed-overlapping
transfer end followed immediately by the next line. This changes only paper
rendering, not the GOINO handshake or physical return timing. Repeating the
same 50-second CATALOG run after the fix yielded 1,300 columns, 315 feed rows,
a peak head position of x=1711 (no frames at the x=1735 paper edge), and
separate rows of ink on the bitmap-printer screen.

An interactive native P6066 compilation-disk printer-only startup also
printed a complete firmware-identifiable header on the paper image. Its
saved paper image and independent font decoding are in the outer repository
at `analysis/mame-p6066/pr6610/`. MAME's shared bitmap-printer viewer can
overlay a numbered inch scale at the right edge: its `0` and horizontal ticks
are not guest-printed data. The PR 6610 now defaults this option to `Off`,
without changing other MAME printers. It can be changed under **Tab →
Machine Configuration → Bitmap Printer Device → Draw Inch Marks**. An existing
MAME configuration can retain a previous `with numbers` selection; select
`Off` there if necessary.
The viewer's green printhead-position marker is also not printed data.
Its **Show Printhead** setting is independently selectable in the same menu;
the PR 6610 defaults it to `Off` while other bitmap printers retain `On`.

ROM-free checks can be run with `python3 scripts/puce/test_pr6610_render.py`
and `python3 scripts/puce/test_pr6610_video.py` from the MAME checkout.
The first compiles the production render/tick methods and verifies asymmetric
dot rows, horizontal advance and feed accumulation against pixel coordinates.
The second places GO011 and a GOINO-state printer fixture on the same
production backplane, transfers data through its selection/dispatch callbacks,
and checks that the production GO011 and PR6610 rendering methods keep both
outputs intact. The existing `test_goino_integration.py` independently
exercises the actual GOINO board callbacks. These synthetic tests do **not**
establish that an original guest simultaneously drives both devices, or
validate the combined view through MAME's live video renderer. The preboot
hardware gate remains closed.

## Unresolved (see TBD.md)

* **Dot polarity.** Bit 0 is rendered at the top, consistent with the
  recovered firmware glyphs and the verified CONDY display font orientation
  (`analysis/charset/README.md`). Physical printer bit-to-head wiring is
  not independently documented; printer evidence could establish a different
  orientation.
* **Paper width and left margin.** The 210 mm roll and 28 px margin are
  functional choices, not measured PR 6610 geometry.
* **Mechanical timing.** The carriage advance is per served column, not the
  180-char/s motor timeline; feed pacing is the 6.3 ms scheduler's, not UMO20.
* **Interline in plotter mode.** The 1/10" interline option (6 steps) is
  implemented in the feed bookkeeping but no GTL3.2 command for it is known.
* **Command polarity conflict.** The F1/F/VIASN/FISTN conflict documented in
  [discard-printer.md](discard-printer.md) is inherited unchanged.
